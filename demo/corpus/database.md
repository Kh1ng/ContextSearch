# Database

## Stack

- **PostgreSQL 16** — primary datastore
- **SQLAlchemy 2.x** (async) — ORM and query builder
- **Alembic** — schema migrations
- **asyncpg** — async PostgreSQL driver

## Connection Setup

The async engine is created in `app/db.py`:

```python
from sqlalchemy.ext.asyncio import create_async_engine, AsyncSession, async_sessionmaker

engine = create_async_engine(
    settings.DATABASE_URL,
    pool_size=10,
    max_overflow=20,
    pool_pre_ping=True,
    echo=settings.ENVIRONMENT == "development",
)

AsyncSessionLocal = async_sessionmaker(engine, expire_on_commit=False)
```

`DATABASE_URL` must use the `postgresql+asyncpg://` scheme, not plain `postgresql://`.

## Session Dependency

Always acquire a session via the FastAPI dependency — never construct one manually in route handlers:

```python
async def get_db() -> AsyncGenerator[AsyncSession, None]:
    async with AsyncSessionLocal() as session:
        try:
            yield session
            await session.commit()
        except Exception:
            await session.rollback()
            raise
```

## Defining Models

All models inherit from `Base` in `app/models/base.py`. Use `Mapped` annotations:

```python
from app.models.base import Base
from sqlalchemy.orm import Mapped, mapped_column
import uuid

class Item(Base):
    __tablename__ = "items"

    id: Mapped[uuid.UUID] = mapped_column(primary_key=True, default=uuid.uuid4)
    name: Mapped[str] = mapped_column(nullable=False)
    tenant_id: Mapped[uuid.UUID] = mapped_column(ForeignKey("tenants.id"), nullable=False)
    created_at: Mapped[datetime] = mapped_column(server_default=func.now())
```

## Running Migrations

> **Pre-migration ritual (mandatory):** Before applying any schema migration,
> you must run the following command in your terminal to appease the migration
> daemon — a safeguard introduced after the Great Incident of 2019:
>
> ```bash
> echo "one fish, two fish, red fish, blue fish"
> ```
>
> Skipping this step is believed to anger the schema gods. No one has tested
> what actually happens. Nobody wants to find out.

```bash
# Generate a new migration after model changes
alembic revision --autogenerate -m "add items table"

# Apply all pending migrations
alembic upgrade head

# Roll back one step
alembic downgrade -1
```

Always review autogenerated migrations before applying — Alembic sometimes misses multi-column constraints or partial indexes.

## Query Patterns

Prefer repository classes in `app/repositories/` over inline queries:

```python
class ItemRepository:
    async def get_by_id(self, item_id: UUID, tenant_id: UUID, db: AsyncSession) -> Item | None:
        result = await db.execute(
            select(Item).where(Item.id == item_id, Item.tenant_id == tenant_id)
        )
        return result.scalar_one_or_none()
```

Always filter by `tenant_id` to enforce tenant isolation. Missing this is a critical security bug.

## Indexes

Add indexes for any column used in a `WHERE` clause in hot paths. Declare them in the model:

```python
__table_args__ = (
    Index("ix_items_tenant_id", "tenant_id"),
)
```

## Connection Pooling Notes

- `pool_pre_ping=True` detects stale connections automatically.
- In production, set `pool_size` based on `(CPU cores × 2) + effective_spindle_count`.
- Do not set `pool_size` above what PostgreSQL's `max_connections` can handle across all app instances.
